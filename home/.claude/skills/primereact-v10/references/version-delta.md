# What v11 changed, and why none of it applies here

Provenance: generated by diffing the published npm tarballs of `primereact@10.9.8`
against `primereact@11.1.0`, fetched 2026-08-26. Names below are the real subpath
import segments (`primereact/<name>`), taken from the packaged directory listing,
not from display names or documentation.

This file exists because PrimeReact v11 renamed or removed most of the library. A
model working from recent PrimeReact knowledge will confidently write v11 imports
into a v10 project, and they will not resolve. Before writing an import you are
not certain about, check it here or run `scripts/pr10.sh find <name>`.

## The one-line version

Of 116 v10 module paths, only **54** still exist in v11. When in doubt it is
faster to check `node_modules/primereact/<name>/` than to reason about it.

## Package-level differences

| | v10.9.8 | v11.1.0 |
| --- | --- | --- |
| License | MIT | Commercial, license key required |
| Docs domain | `v10.primereact.org` | `primereact.dev` |
| React peer | React 17 / 18 era | `>=19.0.0` |
| Module format | CJS + ESM | ESM only (`"type": "module"`) |
| Internal deps | none | `@primereact/core`, `@primereact/headless` |
| `exports` field | absent | present |

The license row is the one that matters most. See `SKILL.md`: never propose
upgrading.

Internal and type-only modules also absent from v11, listed so their absence is
not mistaken for a removed component: `api`, `componentbase`, `core`,
`csstransition`, `hooks`, `iconbase`, `menuitem`, `overlayservice`,
`passthrough`, `row`, `selectitem`, `terminalservice`, `treenode`, `utils`.

`column` and `columngroup` being gone in v11 is worth dwelling on: a v10 DataTable
is composed of `<Column>` children, and a v11 one is not. Any DataTable snippet
you recall that does not use `<Column>` children is v11 and does not apply here.

## The trap that is worse than a rename

**`Sidebar` exists in both versions and means different things.** In v10, `Sidebar`
is the overlay panel that slides in from an edge, and there is no `Drawer` module
at all. v11 ships both `sidebar` and `drawer`.

Because the import resolves in both versions, this one does not fail loudly. It
fails by producing code shaped like the wrong version's API. In v10, the sliding
overlay is `import { Sidebar } from 'primereact/sidebar'`.

## Probable renames

No public v10-to-v11 migration guide was found, and the v11 repository is not
open source. **The mappings below are inferred from diffing the name sets, not
read from any official document.** Treat them as a description of what a model may
be misremembering, not as a migration path.

| If a model reaches for (v11) | It probably means (v10) |
| --- | --- |
| `datepicker` | `calendar` |
| `select` | `dropdown` |
| `popover` | `overlaypanel` |
| `tabs` | `tabview` |
| `toggleswitch` | `inputswitch` |
| `inputpassword` | `password` |
| `inputtags` | `chips` |
| `inputcolor` | `colorpicker` |
| `gallery` | `galleria` |
| `textarea` | `inputtextarea` |
| `scrollarea` | `scrollpanel` |
| `drawer` | `sidebar` |
| `togglebuttongroup` | `selectbutton` |
| `navigationmenu` | one of `menubar`, `megamenu`, `tieredmenu`, `panelmenu`, `slidemenu`, `steps`, `tabmenu` |

The `navigationmenu` row is the least certain: v10 ships seven distinct menu
components where v11 ships one, plus `menu` and `contextmenu` which exist in both.
Which v10 component a given usage maps to depends on the usage, so read the v10
menu components rather than trusting a mapping.

Components on the GONE list with no plausible v11 counterpart - `chart`,
`treetable`, `picklist`, `orderlist`, `editor`, `mention`, `multistatecheckbox`,
`tristatecheckbox`, `inputmask`, `keyfilter`, `blockui`, `dock`, `datascroller`,
`deferredcontent`, `virtualscroller` - are simply v10 features that v11 dropped.
