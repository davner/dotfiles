# Project notes for agents

Run `./test.sh` before proposing a commit. It needs no sudo and touches nothing
outside a temp directory, so there is no reason to skip it. `--fast` drops the
flake evaluations when only the shell scripts changed, and `nix develop
--command ./test.sh` adds shellcheck and actionlint - run it that way when you
touched a shell script or a workflow, since bare it silently skips both.

`.github/workflows/test.yml` runs the fast half on every push; `weekly.yml`
runs the full suite plus a real `nix build` of every configuration on Mondays.
Anything slow belongs in weekly.yml, not in the push path.

## Deliberate decisions

Each has an ADR in `docs/adr/` with the reason. Read the ADR before changing
the thing it names; revert one only with the user's explicit word.

- Homebrew cleanup is `zap` ([0001](docs/adr/0001-homebrew-cleanup-zap.md)) and upgrades on every rebuild, with `claude-code@latest` as the cask ([0002](docs/adr/0002-homebrew-upgrade-on-activation.md)).
- One `darwinConfigurations` entry per username ([0003](docs/adr/0003-one-darwin-configuration-per-user.md)); `users.sh` owns the attrset's shape ([0004](docs/adr/0004-users-attrset-shape.md)); dots in a username become dashes in its flake attribute ([0005](docs/adr/0005-dots-become-dashes-in-flake-attributes.md)).
- home-manager backs up clashing files instead of forcing ([0006](docs/adr/0006-home-manager-backups.md)).
- Claude settings are merged from `settings.base.json`, not linked; `model`, `effortLevel` and `theme` stay out of the base file ([0007](docs/adr/0007-claude-settings-merge-not-link.md)).
- `CHANGELOG.md` is generated by `git-cliff` on `main`: never hand-edit or regenerate it, and pull with `--rebase` ([0008](docs/adr/0008-changelog-generated-by-git-cliff.md)).
- Third-party skills are pinned `flake = false` inputs linked into `~/.claude/skills/` and `~/.agents/skills/`; `npx skills` is retired ([0009](docs/adr/0009-third-party-skills-are-pinned-flake-inputs.md)).

## Skills this repo owns

Every skill under `home/.claude/skills/<name>/` is linked into
`~/.claude/skills/` **one entry per skill**, never as the whole directory:
that directory also holds the third-party skills and `impeccable`, and a
directory-level link would displace them. `home.nix` discovers the folders, so
adding a skill is adding its folder - then `git add` it before a rebuild, since
the flake sees only tracked files and skips an untracked folder silently.
Full-mode `test.sh` fails on any skill folder the evaluated config does not
link.

Rules under `home/.claude/rules/` are linked one file at a time for the same
reason, but not discovered: adding one is a new
`home.file.".claude/rules/<name>.md"` line in `home.nix`.

`to-spec`, `to-tickets` and
`implement-spec` point at `setup-dan-skills`, and `code-review` runs without it;
every skill that reads the glossary honors the paths in `docs/agents/domain.md`; `pr` returns only a paste-ready title and body, after proving no AI is credited in the commits or body; `prototype`,
`code-review`, `implement`, `implement-spec`, `retro` and `setup-dan-skills`
call `impeccable` for UI work. `setup-dan-skills`, `tailwind-v4`,
`primereact-v10` and `making-clipart-gifs` are original to this repo.

## Installing the skills

`home/AGENTS.md` points here, so keep this heading's name stable.

Third-party skills come from the flake. Each source repo is a `flake = false`
input in `flake.nix`, and the `thirdPartySkills` attrset in `home.nix` maps a
skill name to its folder in an input; a rebuild links each one into both
`~/.claude/skills/` and `~/.agents/skills/`. The attrset name must equal the
`name` in that `SKILL.md`, which full-mode `test.sh` checks. To add one: an
input line (if the repo is new), `nix flake lock`, then an attrset line. The
weekly `update.yml` PR bumps them with everything else.

The obsidian plugin is declared in `settings.base.json` and Claude Code
installs and updates it itself.

`impeccable` is the one manual install: it writes hooks and files into its own
folder, which a read-only store path cannot hold. It lands as a real directory
under `~/.claude/skills/`. On a fresh machine, from `~`:

```sh
npx impeccable install   # when prompted for location, choose "global"
```

`npx impeccable update` upgrades it and `npx impeccable check` says whether you
are behind. Both resolve against the working directory, so run them from `~`;
anywhere else they report `Impeccable is not installed in this project` and
exit without checking.

A machine set up before the flake inputs still has the old `npx skills`
copies, and the first rebuild would back each clash up as `<name>.backup`.
Clear them first, with `find-skills` and `skill-creator`, which nothing
manages any more, then rebuild:

```sh
for s in gh-axi chrome-devtools-axi lavish humanizer shadcn migrate-radix-to-base typescript-style-guide \
  find-skills skill-creator; do
  npx skills remove "$s" -g -y
done
rm -rf ~/.agents/skills/impeccable   # a stray copy; the real one is under ~/.claude/skills
./rebuild.sh
```
